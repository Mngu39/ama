# 강화학습 성능평가 및 플레이 리플레이

## 1. 공통 평가 프로그램

현재 기본 평가 프로그램:

`evaluation/evaluate.py`

실행 예시:

```bash
python -m evaluation.evaluate \
  --policy teams.template.random_baseline.eval_policy \
  --episodes 100 \
  --seed 100000
```

옵션:

| 옵션 | 의미 | 기본값 |
|---|---|---|
| `--policy` | 평가할 Python 정책 모듈 | 무작위 기준선 |
| `--checkpoint` | 학습된 모델 가중치 경로 | 없음 |
| `--episodes` | 평가 에피소드 수 | 100 |
| `--seed` | 첫 평가 시드 | 100000 |

시드는 에피소드마다 1씩 증가합니다.

예를 들어 `--episodes 100 --seed 100000`은 100000부터 100099까지의 시드를 사용합니다.

## 2. 현재 측정하는 성능 지표

| 지표 | 정의 |
|---|---|
| Average score | 에피소드별 누적 점수의 평균 |
| Mean max chain | 에피소드별 최대 연쇄 수의 평균 |
| Average turns | 에피소드별 착수 수의 평균 |
| Gameovers | 실제 게임 진행 불가능으로 종료한 에피소드 수 |
| Turn limits | 50착수 제한에 도달한 에피소드 수 |

### Mean max chain

각 에피소드에서 발생한 최대 연쇄 수를 다음처럼 정의합니다.

\[
M_i=\max_t C_{i,t}
\]

여기서 \(C_{i,t}\)는 에피소드 \(i\)의 \(t\)번째 착수에서 발생한 연쇄 수입니다.

최종 지표:

\[
\text{Mean Max Chain}=\frac{1}{N}\sum_{i=1}^N M_i
\]

현재 프로젝트의 기본 목표가 큰 연쇄를 만드는 것이므로 핵심 비교 지표로 사용합니다.

### Average score

각 에피소드의 누적 점수:

\[
S_i=\sum_t s_{i,t}
\]

최종 평균:

\[
\text{Average Score}=\frac{1}{N}\sum_i S_i
\]

큰 연쇄뿐 아니라 여러 차례의 소규모 소멸로도 점수를 얻을 수 있으므로, 최대 연쇄 수와는 다른 성능 특성을 측정합니다.

## 3. 현재 무작위 정책 기준선

다음 조건에서 측정한 결과입니다.

- 정책: 무작위 합법 착수
- 평가 시드: 100000~100099
- 에피소드 수: 100
- 최대 착수 수: 50

| 지표 | 결과 |
|---|---:|
| Mean max chain | 1.920 |
| Average score | 1,244.50 |
| Average turns | 40.16 |
| Gameovers | 68 |
| Turn limits | 32 |

이 값은 현재 구현과 평가 조건에 한정된 참고용 기준선입니다.

무작위 정책의 결과에는 정책 난수도 영향을 미칠 수 있으므로, 더 엄밀한 비교에서는 정책 난수 시드 역시 기록해야 합니다.

## 4. 추가로 고려할 수 있는 평가 지표

| 후보 지표 | 의미 | 활용 |
|---|---|---|
| Median max chain | 최대 연쇄의 중앙값 | 극단값 영향 감소 |
| Std. dev. of max chain | 최대 연쇄의 표준편차 | 성능 안정성 |
| \(P(M\geq k)\) | k연쇄 이상 달성 비율 | 목표 연쇄 달성 확률 |
| Maximum achieved chain | 전체 평가 중 가장 큰 연쇄 | 최고 성능 |
| Mean chain per move | 착수당 평균 발생 연쇄 | 연쇄 빈도 |
| Mean chain on trigger | 연쇄가 발생한 착수에서의 평균 연쇄 | 발화 품질 |
| Time to first k-chain | 처음 k연쇄를 달성하기까지의 착수 수 | 학습된 전략의 효율성 |
| Average score | 누적 점수 평균 | 점수 성능 |
| Maximum single-chain score | 한 번의 연쇄에서 얻은 최대 점수 | 큰 발화의 품질 |
| Gameover rate | 게임오버 비율 | 생존 안정성 |
| Average survival turns | 평균 착수 수 | 생존 길이 |
| Learning curve | 학습 진행에 따른 성능 | 데이터 효율성 |
| Wall-clock training time | 실제 학습 시간 | 계산 효율성 |
| Simulation steps/sec | 초당 게임 착수 처리량 | 학습 환경 속도 |

### 권장 비교 지표

우리 프로젝트처럼 큰 연쇄 생성이 핵심이라면 다음을 우선 고려할 수 있습니다.

**주요 지표**

- Mean max chain
- Median max chain
- \(P(M\geq 3)\), \(P(M\geq 5)\), \(P(M\geq 8)\) 등 목표 연쇄 달성 비율

**보조 지표**

- Average score
- Gameover rate
- Average survival turns
- 학습량 대비 성능
- 학습 시간 대비 성능

평균 최대 연쇄 수가 높더라도 일부 시드에서만 극단적으로 큰 연쇄가 발생한 결과일 수 있습니다. 중앙값과 목표 연쇄 달성 비율을 함께 측정하면 이를 구분하는 데 도움이 됩니다.

다른 지표를 더 중요하게 생각하거나 새로운 평가 기준을 제안하고 싶은 경우 **카카오톡으로 의견을 공유해 주세요.** 특히 평균 연쇄의 정의와 평가 착수 수 등은 최종 실험 전에 팀 차원에서 확정할 필요가 있습니다.

## 5. 공정한 모델 비교

서로 다른 보상함수로 학습한 모델을 비교할 수 있습니다.

예를 들어 A 모델은 점수 중심, B 모델은 연쇄 수 중심으로 학습하더라도 두 모델을 평가할 때는 같은 환경을 사용합니다.

비교 시 고정할 항목:

- 동일한 게임 시뮬레이터 버전
- 동일한 평가용 시드 집합
- 동일한 최대 착수 수
- 동일한 공개 NEXT 정보
- 동일한 게임오버 조건
- 동일한 평가 지표

추가로 학습 에피소드 수, 총 학습 착수 수, 모델 구조, 하이퍼파라미터, 보상함수와 체크포인트 정보를 기록하는 것을 권장합니다.

가능하면 학습 중에 사용한 시드와 최종 평가 시드를 분리합니다.

현재의 50착수 제한은 임시 설정이며, 실제 연구에서 사용할 길이는 별도로 논의해야 합니다.

## 6. 학습된 모델 평가 인터페이스

각 실험에서 `eval_policy.py`를 제공합니다.

```python
def make_policy(checkpoint=None, seed=0):
    ...
    return policy
```

반환된 객체는 다음 메서드를 구현해야 합니다.

```python
policy.select_action(observation, legal_mask)
```

선택한 행동은 0~21 사이의 합법적인 행동 ID여야 합니다.

에피소드 시작 때 내부 상태를 초기화해야 하는 정책이라면 선택적으로 `reset_episode()` 메서드를 제공할 수 있습니다.

평가 프로그램은 현재 학습용 `reward.py`를 호출하지 않습니다.

신경망 정책은 평가 중 탐색 노이즈, Dropout, 학습 업데이트 등의 처리 방식을 명확하게 설정해야 합니다.

## 7. 한 에피소드의 플레이 시각화

원본 Ama 프로젝트에는 PuyoP 사이트의 플레이 리플레이 URL을 생성하는 코드가 있습니다.

예시 URL:

http://www.puyop.com/s/_3c5cco8K7wcM7IfmdQcMiMiEfc183IhQfKiM3Cbifuigfmc8cwio1kfgdk0o3sgA1E8K1E6igA

브라우저에서 이 링크를 열면 해당 착수 시퀀스를 시각적으로 살펴볼 수 있습니다.

기존 Ama 탐색 AI로 리플레이를 만드는 방법:

```bash
make PEXT=true puyop
./bin/puyop/puyop.exe 12345
```

출력된 URL을 브라우저에 붙여넣으면 됩니다.

**중요:** 이 실행은 기존 Ama 탐색 AI를 사용합니다. 팀원이 만든 RL 모델의 플레이를 보여주는 것은 아닙니다.

현재 `PuyoEnv`에는 리플레이 URL 생성 기능이 연결되어 있지 않습니다. RL 모델에서 URL을 만들려면 해당 에피소드의 뿌요 쌍과 선택한 행동 번호를 기록한 뒤 원본 Ama의 URL 형식으로 인코딩해야 합니다.

별도의 `evaluation/replay.py` 유틸리티를 추가하여 이 작업을 지원하도록 할 수 있습니다.

## 8. 리플레이 활용 방안

리플레이는 단순한 시각화 외에도 다음 분석에 사용할 수 있습니다.

- 큰 연쇄를 만든 과정 확인
- 연쇄 구조의 형성 및 발화 시점 확인
- 서로 다른 정책의 착수 전략 비교
- 특정 시드에서 실패한 원인 분석
- 연쇄 형성 도중 불필요한 소멸이 발생했는지 확인
- 팀프로젝트 발표용 사례 선정

성과를 설명할 때는 평균 지표뿐 아니라 좋은 사례와 실패 사례를 함께 제시하는 것을 권장합니다.

## 9. 현재 평가 시스템의 한계

현재 프로그램에는 다음 기능이 추가로 필요할 수 있습니다.

- 에피소드별 CSV/JSON 기록
- 신뢰구간 및 표준편차 계산
- 학습 중 주기적 평가
- 여러 체크포인트 비교
- 평가 결과 그래프 자동 생성
- 모델별 플레이 리플레이 URL 저장
- 공통 평가 시드 목록 파일
- 평가용 착수 제한 설정
- 모델 추론 시간 및 학습 시간 측정

이 기능들은 현재 기본 평가 프로그램에 모두 구현되어 있는 것은 아닙니다.

팀원들의 실험이 진행되면서 필요한 기능부터 추가할 예정입니다.
