# 가설 2 — Short vs Long Horizon 연동 규약

## 소유 범위

- **민찬님 담당(이번 패키지)**: 선정 GTR 공통 베이스라인, 파라미터 프로필, n-step 유지, Kaggle 테스트 노트북, 로그/비교 도구, 예측 모델 인터페이스 규약 정리.
- **민규님 후속 담당**: 뿌요 생성 확률 검증, Uniform/예측 모델 구현, Long Horizon 탐색 로직, 가설별 본 실험, 팀내 분담.
- **태형님**: 발표 분석/설명.

## 실험 계획(미실행)

| 군 | 정보 | 평가 정책 | 목표 |
| --- | --- | --- | --- |
| A | 현재 공개된 3쌍 | 원본 GTR 3-ply | Short baseline |
| B | 공개 3쌍 + 4/5번째 균등확률 | 5-ply 구현 필요 | 탐색 수평선 증가 효과 |
| C | 공개 3쌍 + 예측 AI의 4/5번째 확률 | B와 같은 5-ply 탐색 구현 필요 | 예측 분포의 부가 가치 |

**주의:** 가설 2는 `--n-step=5`와 무관함. `--n-step`은 TD 보상 누적 기간이고 5-ply는 탐색 수평선임. 별도 합의가 없다면 공통 GTR 백본은 `--n-step=1`로 학습한다. B/C 평가 탐색과 뿌요 예측 AI는 이 인계본에 **구현되지 않음**.

## 학습 프로필

공통 확정 설정 `H2_GTR_COMMON_20K_B30K_E500K`: Buffer 30,000(11월 7일 회의에서 공통 조건으로 채택), Epsilon 0.40→0.02 over 500,000 *환경 스텝*(Buffer 30k 고정·5k 사전 학습의 E250k/E500k 3-ply 250판 비교로 선정), LR 0.0001, batch 16, gamma .995, PER alpha .6/beta .4→1.0, GTR 계수 .04, 20k 에피소드 **처음부터 신규 학습**, 1-ply 학습·매 500판마다 1-ply 100판 검증 및 최고 연쇄 모델 보존·최종 3-ply 250판 별도 평가. Buffer 30k 자체가 10k보다 우월하다고 검증된 것은 아닙니다.

## 미래 정보 누출 방지

1. 게임 엔진 내부가 이미 만들어둔 미래 시퀀스를 평가용 **정답 레이블**로 읽을 수 있더라도, 에이전트/예측 AI에는 시점 t에 실제 공개된 정보만 입력해야 함.
2. 예측 AI 학습용 시퀀스와 정책 성능 평가용 시드/게임을 분리. 예측 성능은 별도 검증 데이터에서 측정.
3. 16개 색쌍 순서·동색 가능 여부·128-piece bag/제약 여부는 **게임 엔진에서 검증 후** 고정해야 함. 단순히 16가지가 모두 독립 균등이라고 가정하면 틀릴 수 있음.
4. B/C는 동일 5-ply 탐색 방식과 동일 계산 예산을 사용. A(3-ply)와 B(5-ply)의 성능 차이를 예측기 성능으로 해석하지 않음.

## 결과 저장

- 기존 `puyo_train.py evaluate`는 **`episodes.csv`** / `summary.json` / `moves.csv.gz`로 실행별 점수·최대 연쇄·총 탐색 후보·의사결정 시간 등을 이미 기록.
- 후속 B/C 정책도 **같은 열 이름**(`seed,total_score,max_chain,turns,simulated_candidates,evaluated_candidates,decision_time_seconds` 등)으로 기록하면 `analysis/horizon2_compare.py`로 A/B/C를 직접 비교할 수 있음.
- B/C에는 `variant` 구분을 포함한 `horizon2/experiment_contract.json` 같은 메타데이터를 동봉. 분석기는 모델명과 시드 집합·데이터 무결성을 확인하지만 알고리즘 동일성까지 자동 증명하지 않음.
- 예측 AI 평가를 하려면 `future_prediction_log_template.csv` 구조를 활용. **빈 템플릿이지 결과가 아님.** 16개 확률 값을 일관된 색쌍 순서로 기록하고, 정답은 평가 시점 이후에만 연결.
- 결과 해석: 평가 평균 점수/최대 연쇄/7연쇄율, 소요시간/게임, 후보 평가수/턴, seed별 차이를 구분해서 비교. `train_episodes.csv`는 탐험 포함 학습기록으로 평가 성능과 혼동 금지.

## 넘길 때 확인할 사항

- [ ] Buffer 30k 회의 채택·Epsilon 500k 사전 실험 선정 근거를 확인하였는가?
- [ ] 선정된 공통 파라미터로 0→20,000에피소드를 신규 학습하였는가? 5k 가중치는 사전 실험의 증빙이며 본 학습 초기 가중치가 아닙니다.
- [ ] A/B/C가 **같은 GTR 체크포인트**를 사용하는가?
- [ ] 게임 엔진 미래 정보 노출 범위, 색쌍 분포 검증 계획을 합의했는가?
- [ ] B/C 5-ply 구현 담당·연산 예산을 확정했는가?
- [ ] 3-ply 평가 250판 시드 100000~100249 및 평가 종료 조건을 고정했는가?

**실행 상태:** 이 패키지는 표준화·통합·기록 분석에 중점을 둔 인계본이다. B/C 실제 정책, 예측 AI와 20k 본 실험은 아직 실행하거나 구현하지 않았다.
